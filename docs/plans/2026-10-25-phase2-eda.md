# Phase 2 — EDA Implementation Plan

**Goal:** Answer the questions that decide the Phase 3 models, from data already in the lake, with one repeatable command (`nea eda`) that prints numbers, saves charts, and feeds a short findings doc.

**Architecture:** `src/nea_forecast/eda.py` holds one function per question. Each takes a DuckDB connection, runs SQL against `gold.*` / `silver.*`, returns a plain dict of numbers (always with `n`), and optionally saves a PNG to `data/eda/`. `nea eda` runs them all, writes `data/eda/summary.json`, prints it. `docs/eda-findings.md` is written by hand from that output and ends with the Phase 3 input decisions.

**Tech Stack:** DuckDB SQL (`corr`, `regr_slope`, `regr_r2`, window `lag`), matplotlib (new dep, PNG only), pytest on a synthetic tmp lake.

**Spec:** `docs/blueprint.md` (Mission, Model strategy, Open risks) + user brief: daily short-term, winter seasonal outlook, India import need; simplest model that runs on a laptop.

## Global Constraints

- No LLM in code. Numbers come from SQL; prose in `docs/eda-findings.md` is written after reading `summary.json`.
- Read-only on the lake: `connect(read_only=True)`. EDA never writes lake tables.
- Daily stats use only `qa_ok = true` rows of `gold.daily_features` (4 all-zero days are `false`).
- Every returned stat carries its sample size `n`; a stat with `n < 30` (daily) or `n < 12` (monthly) is reported but flagged `"low_n": true`.
- Units: report everything in **GWh** (monthly/annual) or **MWh** (daily). CERC `*_mu` = GWh; TradeStat `mwh` measure ÷ 1000 = GWh; `report_monthly_balance` rows with `unit = 'GWh'` only.
- BS↔AD: report months are `(fy, bs_month)`; map to the AD month the BS month **starts** in (`dim_calendar` row with that `fiscal_year`, `bs_month`, `bs_day = 1`; BS months start the 13th–18th, so a consistent half-month shift), never by arithmetic. `bs_month` is calendar order: Baishakh = 1, Shrawan = 4.
- Logs: `nea eda` goes through the CLI log tee (`data/logs/<YYYYmmdd-HHMMSS>-eda.log`, every line time-stamped); per question `▶ start`, `✔ done in Xs → chart` + its numbers, `✖ FAILED` (others continue); `== eda done` with failures.
- Charts: `data/eda/<name>.png`, matplotlib default style, one figure per question, titled with the question.
- Conventional Commits. Each task appends to `docs/developer/decisions.md` change log.
- Keep it small: one module, no class, no plotting helpers beyond a 5-line `_save(fig, name)`.

## Review Focus

1. **NDOR gaps (27 missing days) in lag scans** → lag must be computed by date (`date - INTERVAL k DAY` join), not row offset, else a gap shifts every later value. Test in Task 3.
2. **Unit mix-up (MWh vs GWh vs MU)** across import sources → a ratio test with identical synthetic series in different units must give 1.0. Test in Task 5.
3. **BS month mapped to wrong AD month** → report month `2081/82, bs_month 4` (Shrawan) must land on July 2024. Test in Task 5.
4. **Partial months** (NDOR first/last month, months with < 25 reported days) → excluded from monthly comparisons. Test in Task 5.
5. **Tiny samples sold as findings** (annual: 13 points; NDOR: 2 winters) → `low_n` flag set. Test in Task 4.
