# Phase 4 — Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A public, static website that presents the NEA analysis and forecasts to competition evaluators and enthusiasts. It needs:
- interactive charts
- a map of Nepal with the data points
- a SQL console over the same data

It is hosted free on Cloudflare.

**Architecture:**
- **Export:** `nea export` copies lake tables to Parquet under `site/src/data/` with a `manifest.json`. These are the **only** data the site reads: one source of truth, a snapshot of the lake.
- **Site:** Observable Framework turns `site/src/*.md` pages into a static site.
- **In the browser:** charts are SQL queries run by DuckDB-WASM on those Parquet files, drawn with Observable Plot. There is no hand-made JSON.
- **Map:** Leaflet with OpenStreetMap tiles.
- **Deploy:** `npm run build`, then `npx wrangler pages deploy site/dist` (Cloudflare Pages free tier). Builds happen locally, because the lake lives on the laptop.

**Tech stack:** Observable Framework 1.13 (Node 24), DuckDB-WASM, Observable Plot, Leaflet, Cloudflare Pages.

## Global constraints

- Free tier only. Each deployed file must be ≤ 25 MiB, and Pages allows ≤ 20,000 files.
- Every chart's data comes from an exported Parquet file through SQL in the browser. No numbers are hard-coded on pages except narrative text quoting results.
- The SQL console is read-only by construction: it runs in the visitor's browser on static files, with no server and no secrets.
- Write for evaluators: lead with the answer (winter import outlook), keep the method and evidence one click away, and state the limits.
- Plant coordinates added for the map are approximate and labelled so.
- Each step logs `▶` / `✔`, like the other commands.
- Commits via caveman-commit, no Claude attribution. Each step gets a change-log entry in `docs/developer/decisions.md`.

## Review focus

1. A large Parquet export or a DuckDB-WASM bundle file over 25 MiB fails the deploy → check `dist` file sizes before deploying.
2. A stale export (site shows old data) → `manifest.json` carries `exported_at`, and every page shows it.
3. A bad SQL query in the console → show the error message, not a blank page.
4. A map point with wrong coordinates → plant points are flagged approximate in the popup.
5. Mobile → charts use the container width; tables scroll.

## Tasks

### Task 1: `nea export`
- `src/nea_forecast/export.py`: `export(con, out=Path("site/src/data")) -> dict`.
  - One `COPY (...) TO '<table>.parquet' (FORMAT parquet, COMPRESSION zstd)` per table in `TABLES`.
  - Tables: gold views; silver tables except `nea_document`; `ml.backtest_metrics` and `ml.forecasts` limited to the latest backtest run plus all live runs; `bronze.ingest_log`.
  - `points.parquet`: weather and river points from `sources.json`, plus outage plants with approximate coordinates (from `outages.json` `lat`/`lon`, `coord_approx`).
  - `manifest.json`: table → rows, columns, bytes; plus `exported_at`.
- CLI `nea export`.
- Test: `test_export_writes_parquet_and_manifest` on a tmp lake.

### Task 2: Site scaffold and data layer
- `site/package.json` (`@observablehq/framework`, scripts `dev`, `build`, `deploy`), `site/observablehq.config.js` (title, pages, theme).
- `site/src/components/db.js`: one DuckDB client over all manifest tables; `q(sql)` helper.
- Build, then check the size of the largest `dist` file.

### Task 3: Pages
| Page | Content |
|---|---|
| `index.md` Overview | headline: winter 2026/27 import outlook, base vs flood-adjusted with P10–P90; key numbers; the flood; how to read the site |
| `map.md` Map | Leaflet map: weather points, river points (basin / plant), flood-damaged plants; popup with the latest value and a mini chart |
| `data.md` Data | sources and coverage timeline, daily demand/import history, monthly import sources |
| `analysis.md` Analysis | EDA: seasonality, temperature, river flow vs generation/import, long-term growth |
| `models.md` Models | ladder, backtest winter MAE by horizon, selection table, interval coverage, monthly backtest |
| `forecast.md` Forecast | live winter outlook, river-flow forecast vs normal, outage register, daily forecast when available |
| `sql.md` SQL explorer | table list with columns, editable query, result table, quick chart, example queries |
| `method.md` Method | the approach in short, the defence points, limits, sources, link to the repo docs |

- README, `flow.md` and blueprint updated.
